## 📋 Launcher Changelog v0.6.24

### ✨ New Features

#### Events
- **World Cup Public Viewing** - During the event the play screen offers a one-tap "WM Public Viewing" toggle (football icon) that launches the selected profile straight onto **HugoSMP.net** in Minecraft **1.21.11** with the **norisk-prod** pack. The override is applied per-launch only — your profile's own version, loader and pack are never changed — and the promo hides itself automatically once the event ends

#### Profiles
- **Virtualized Profile List** - The profile list now renders through `react-virtuoso`, so large profile counts no longer lag or freeze the ALL tab [#247](https://norisk.gg/issues/247)
- **Multi-Select Version Filter** - The hardcoded version filter (1.21 / 1.20 / 1.19) is replaced by a multi-select filter whose options are derived dynamically from your actual profiles, with counts. This also fixes profiles on an unknown version (e.g. `26.x`) being unreachable and staying hidden on the ALL tab. While a filter is active the list is grouped into version sections with dividers; the group tabs and search header stay pinned above the scroll area [#247](https://norisk.gg/issues/247)

### 🐛 Bug Fixes

#### Downloads
- **Corrupt NRC Pack Jars Caught Before Launch** - NRC's own pack jars are pulled from Maven but were only gated by a ZIP-header heuristic that missed mid-file corruption, letting a damaged jar pass, get cached, and crash the client every launch with `ZipFile invalid LOC header (bad signature)`. The launcher now verifies each jar against its Maven `.sha1` sidecar and re-downloads on mismatch; a missing sidecar falls back to the previous behaviour [#237](https://norisk.gg/issues/237)

### 🧹 Chores

#### Mod Cache
- **Auto-Trash Orphaned Cached Jars** - `meta/mod_cache/` grew unbounded — every new mod or NRC pack version left its old jar behind forever. On startup (debounced to once per 24h, as a detached best-effort task) the launcher now sweeps cache jars that no live profile or resolved pack can reference into the trash, where the existing 30-day retention frees them for good. Guarded so an empty keep-set aborts the sweep and trashing (not deleting) keeps every call recoverable. A Debug › TESTING tab can inspect the keep-set and run the cleanup manually [#242](https://norisk.gg/issues/242)
