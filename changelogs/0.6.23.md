## 📋 Launcher Changelog v0.6.23

### ✨ New Features

#### Crash Analysis & Reports
- **Crash Analysis Modal with One-Click Fixes** - After a crash the launcher now surfaces a dedicated analysis modal that explains the likely cause and offers one-click fix actions instead of dumping a raw log
- **New-Bug Screen & Tracking-Issue Link** - Unrecognized crashes show a "new bug" screen with a direct link to the tracking issue, so players can report and follow a fix
- **Mod Manifest Snapshot at Launch** - The set of enabled mods is snapshotted at launch time, powering an `enable_mod` fix action that can re-enable a mod a crash points at

#### Skins
- **Content-Addressed Skin Rendering** - The play-screen body now renders through Starlight using the applied skin's base64, so the cache key is the skin **content** (sha1). A skin change produces a fresh render immediately — no name-keyed cache staleness and no Mojang CDN propagation lag
- **Local Face Avatars** - Player heads are cropped locally from the skin PNG via the `image` crate (face `8,8→16,16` + hat overlay), content-hashed in `meta/face_cache`, instead of fetching from an external avatar API
- **Vanilla Skin Cache Reuse** - Skin lookups now read the game's own skin cache first (`meta/assets/skins/<h0:2>/<h>`, keyed by `SHA1(UTF-16LE(textureHash))`) and write fresh downloads back into it. Heads load offline and skip redundant texture downloads for any skin the game has already seen — benefitting both launcher and game
- **Mojang Reconcile** - On startup and account switch the active account's skin is reconciled from Mojang, so a skin changed outside the launcher (minecraft.net / in-game) is picked up
- **Reusable `PlayerHead`** - Single head component + `usePlayerAvatar` hook (active account → local face render, other players → by-UUID), adopted across the account bar, account list, friends, chat and profile UIs

#### Launcher Notices
- **Flagsmith-Driven Notice Banners** - Launcher notice banners are now driven by Flagsmith, so messages can be shown/updated remotely without a release

#### Profiles
- **Pack Fallback for Removed NRC Packs** - Profiles pointing at an NRC pack that no longer exists fall back gracefully instead of breaking

#### Config & URLs
- **Production URL Switch** - More services moved to production URLs; selection switched back to `is_experimental`-based once `cms.norisk.gg` was ready

### 🐛 Bug Fixes

#### Skins
- **Own Skin & Avatar No Longer Stale** - After changing your skin via the launcher, the play-screen body and the account head stayed on the old skin until a restart. The launcher now keeps a local source of truth for the active account's applied skin bytes (`active_skins.json`) and emits a `MinecraftSkinChanged` event, so the play-screen body and every account head refresh instantly. Default-skin players and the reset-to-default case are handled too [#9](https://norisk.gg/issues/9)
- **Rust-Side UUID & Token Resolution** - Skin commands resolve the active account's UUID and a freshly refreshed access token in Rust instead of trusting the UI's possibly-stale copy

#### Auth
- **Accounts Stay Visible During Mojang Outage** - Account list no longer empties out when Mojang auth is temporarily down

#### Profiles
- **Per-Entry Profile Loading** - Profiles load per-entry, so a single corrupt profile can no longer wipe out the whole list

#### Cape Ban
- **Frontend Ban-Timestamp Formatting** - Cape ban expiry is formatted on the frontend [#96](https://norisk.gg/issues/96)
- **Localized Ban-Expiry Timestamps** - Ban-expiry timestamp formatting is now localized per language

#### Errors & UI
- **Backend Error Key Translation** - Backend error keys are parsed and translated with a standardized extraction path
- **Idle Rollout Animation** - The rollout bolt animation no longer eats GPU while the window is minimized

### 🧹 Chores
- **Dropped crafatar / mc-heads** - Removed the external Crafatar avatar API (`crafatar_api.rs`, `get_crafatar_avatar`, `useCrafatarAvatar`) and the hardcoded `crafatar.com` fallbacks. All player heads now derive from a single local pipeline (`get_face_avatar`), with the vanilla skin cache + Mojang as the only sources
- **Skin Helper Cleanup** - Shared `normalize_uuid`, `atomic_write` (temp + rename) and `fetch_skin_base64_for_uuid` helpers de-duplicate the skin fetch / write paths
- **Issue Tracker URLs** - Updated issue tracker / flatpak issue URLs
